# E08-G：MVMD 模态级稳定性 + 中心频率阻尼更新消融（开发性试验）

## 原因与实测依据

- E08-F 中 W9-60（传统窗口） K8/154.158、K7/450、K8/320 在 **2400** 次全部未达到 `tol=1e-5`，尽管 AC 相对重构误差分别仅约 0.263%、0.724%、0.467%。不能把非收敛输出算进 RMSE。
- W9-60 尾段窗口中某些迭代的模态和中心频率变化有跳动，因此可检验**中心频率更新阻尼**是否提高收敛稳定性，而不随意修改 K、alpha 或放宽容差。
- Z9-3 的原窗口仅 1829 点，被错误跳过；尾段3000点后三个参数均收敛（837、337、471次）。

## 实验与干预

复用原版 MVMD 的镜像、逐模态 Gauss–Seidel 更新、`tau=0`、`alpha`、模态频率更新目标与三次连续停止门槛，**只修改中心频率的更新速率**：

`omega_next = (1-eta)*omega_old + eta*omega_energy_centroid`。

- `eta=1.0` 是 E08F 原方案；`eta=0.5` 是预先固定的单一阻尼方案。它们的**固定点频率方程**一致，但中间轨迹、时间和数值局部极值可能不同。
- 三组 **完全冻结** 参数：K8/154.157959862、K7/450、K8/320。
- 两个已经用于开发的文件：W9-60、Z9-3，均使用统一尾段3000点。
- 最大2400迭代，**两种方法的停止条件相同**：模态delta < 1e-5、**未阻尼的能量重心目标差** <0.01 Hz（即使 eta=0.5 也使用原目标差作为停止判据，不会人为变宽）、连续3次。AC相对残差限制0.15。
- 快照600/1200/1800/2400次（若提前收敛只保留达到的节点与最终节点）；计算所有模态的能量、变化量贡献与中心频率。使用与 E08E 一致的硬重构分类作为**快照诊断**，不将非收敛快照当作有效滤波结果。

## 运行

1. 解压工程；将 MATLAB 当前目录设为本文件所在目录。
2. 修改 `E08G_config.m` 的 `cfg.dataRoot` 为包含 `W9-60.TXT` 与 `Z9-3.TXT` 的真实数据根目录（递归寻找）。
3. 在 MATLAB 命令行执行：

```matlab
E08G_run
```

预计共执行 **2个数据文件 × 3组冻结参数 × 2种中心频率更新 = 12次MVMD求解**。会保存中间CSV，求解失败不会清空已完成结果。不要同时开启其他高预算MVMD任务。

输出位置：`results_E08G`。

| 文件 | 主要作用 |
|---|---|
| `E08G_solver.csv` | eta=1与0.5的收敛比例、迭代次数、AC误差、用时 |
| `E08G_modes.csv` | 每个IMF的频率、能量份额、局部变化量及其对全局变化量的贡献 |
| `E08G_checkpoints.csv` | 每个迭代检查点的双通道9 Hz基频幅相、未阻尼目标差和实际中心更新步长、硬重构状态 |
| `E08G_output_stability.csv` | 同一算法早期快照相对最终快照的重构稳定性；**不能单凭此认定收敛** |
| `E08G_issues.csv` | 文件缺失、异常或求解失败记录（存在问题时生成） |
| `E08G_config_frozen.mat` | 固定实验配置 |

## 决策规则（先于数据确定）

1. 若 eta=0.5 在 W9-60 产生符合**原始严格判据**的解，且 Z9-3 仍正常收敛，说明阻尼具有开发性潜力；下一轮应统一加入训练求解器、重新公平自动寻优，并在**其他未参与诊断文件**确认改善。
2. 若 W9-60 仍全部不收敛：查看 `E08G_modes.csv` 的 `globalChangeFraction`，判断是否只有少数弱能量IMF拖慢整体更新；同时查看 `E08G_output_stability.csv` 的重构稳定性，再决定是否实施**基于输出与物理保真的可审计双层停止准则**。不能把该准则当作原始严格收敛的替代品。
3. 若阻尼造成收敛变差，记录失败，**恢复 eta=1**，不要围绕已看过的W9-60遍历任意 eta 数值。

本轮不研究动态零偏和灵敏度，不叠加新滤波器，不产生姿态角或真值RMSE。后续仍以物理一致性 FVIM-MVMD 自动选 K/alpha 为路线A，固定参数为路线B。

## 实验限制

文件已做依赖与打包检查，但没有在用户 MATLAB 和真实 TXT 上执行；严禁提前宣布阻尼改善。阻尼法不等于论文作者原版FVIM，该工程也没有重新实现FVIM本身。
